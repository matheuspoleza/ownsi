# ADR-0020 — A pluggable product, not a hosted app

## Status

Accepted. Revises [ADR-0005](0005-two-level-identity.md) and triggers
[ADR-0021](0021-webhook-primary-email-optional.md).

## Context

Everything up to here specified the domain logic but assumed a single hosted app as the delivery
shape. Two alternatives were on the table: a hosted app, or a portable attestation network ("Stripe
Link, for domains") — prove once, reuse everywhere.

## Decision

Ownership proof is delivered as an integrable product — an HTTP API, `@ownsi/node` (server),
`@ownsi/react` (drop-in component + headless hook) and docs. The hosted app stops being the product
and becomes the **first consumer of the public SDK**: it imports the same package a customer would.

## Consequences

1. **It dissolves the trust problem.** A portable attestation network would require the relying party
   to accept an external issuer's assertion at a privilege-escalation boundary — verifying
   `acme.com` in something like Okta usually unlocks claiming every `@acme.com` user. In the
   pluggable shape there is no third-party assertion: **each app runs its own verification, with its
   own token, in the same zone. What is shared is code, not trust.**
2. **It is the surface the evaluation measures.** Docs, API design and DX are what Resend does and
   what it looks at. A hosted app demonstrates one screen; a package demonstrates a product.
3. **Low marginal cost.** All the domain logic ([ADR-0004](0004-txt-record-on-underscore-host.md),
   [ADR-0006](0006-events-checks-and-three-valued-outcome.md),
   [ADR-0009](0009-recursive-decides-authoritative-explains.md),
   [ADR-0011](0011-check-cadence.md)–[ADR-0013](0013-revocation-with-reversible-grace.md),
   [ADR-0015](0015-provider-specific-setup-instructions.md)–[ADR-0019](0019-notification-policy.md))
   was already specified. What is added is packaging, not new product.
4. **The justification for the dependency already exists.** Rendering "create a TXT record" is an
   afternoon's work for anyone. What nobody writes on their own is
   [ADR-0015](0015-provider-specific-setup-instructions.md) (Cloudflare calls it "Name" and wants
   `_x`; GoDaddy calls it "Host" and auto-appends the domain) and
   [ADR-0016](0016-active-diagnosis-probe-catalogue.md) (the 12 probes with named cause and fix).
   **The copy is the product.**

**Rejected — a portable attestation network.** Beyond the trust boundary, the economics do not work.
Link works because Stripe was already in the payment path before launching it, and because it removes
30 seconds of friction at very high recurrence. Here the median is 3 minutes and it happens once per
company per vendor — the value lives in the tail, which is an insurance model, not a network model.
And the natural issuer would be whoever is already in the zone (Cloudflare, Vercel, the registrar),
not a third party.

**Precedent recorded:** the `hd` claim in Sign in with Google is a domain attestation network running
in production — and it confirms the argument, because Google can only issue it by having already
verified the domain in Workspace for another reason.

**Architectural consequence:** portable proof could not be a public DNS record anyway. If the TXT in
the zone meant "proved to anyone", then anyone can run `dig` and the proof degrades from "I control
the zone" to "I can read DNS". Portability would require a signed attestation with audience and TTL —
OIDC-shaped, not DNS-shaped. Out of scope, recorded here.

**The hosted app is not a demo.** Calling it a demo demotes exactly what the brief asks for.
`apps/ownsi` **is the product**; `@ownsi/react` is that same product packaged to fit somewhere else.
Precedent: `resend.com/domains` is not a demo of React Email, and the Clerk dashboard is not a demo of
Clerk — it is the Clerk dashboard, which happens to log you in using Clerk. One experience, two
distributions.

**Dogfooding has to be verifiable, not declared.** Ownsi has a row in `apps` like any other, with a
key generated by the same generator and validated by the same middleware. **Invariant: no
`if (app.isFirstParty)` in the core.** The minute one exists, there is a path only Ownsi exercises and
another only the customer exercises — and the second breaks in production. Consequence: another app
works *today*, not "in the future", and the cross-origin example proves it in thirty seconds.

**Scope guard:** the brief asks for *"helps a **user** prove ownership"*. The end user's experience is
the primary deliverable; packaging demonstrates the second dimension and must not eat the first.
Cut order: webhooks → API keys tab → cross-origin example → publishable package. Never the probes of
[ADR-0016](0016-active-diagnosis-probe-catalogue.md), never the pending screen of
[ADR-0012](0012-pending-hibernates-never-expires.md).
